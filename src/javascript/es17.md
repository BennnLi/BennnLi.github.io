# ES17（ES2026）

ECMAScript 第 17 版 · 2026 年 6 月发布

这版只有 7 个提案，都比较"实用向"：数组/迭代器/Map 各补一块，JSON 和二进制各修一个痛点。

## 版本速览
1. `Array.fromAsync()`
2. `Error.isError()`
3. `Iterator.concat()`
4. `Map` / `WeakMap` 的 `getOrInsert()` / `getOrInsertComputed()`
5. `JSON.parse` 能拿到原文（+ `JSON.rawJSON()`）
6. `Uint8Array` 的 Base64 / Hex 方法
7. `Math.sumPrecise()`

## Array.fromAsync()

`Array.from` 的异步版，能把异步可迭代对象收成数组。

````javascript
async function* gen() {
  yield 1
  await null
  yield 2
  yield 3
}

await Array.fromAsync(gen())    // [1, 2, 3]
````

同步的东西也行

````javascript
await Array.fromAsync([1, 2, 3])                       // [1, 2, 3]
await Array.fromAsync([1, 2, 3], x => x * 2)           // [2, 4, 6]
await Array.fromAsync({ length: 2, 0: 'a', 1: 'b' })   // ['a', 'b']
````

**和 `Promise.all` 的关键区别：它是逐个串行的。**

````javascript
const order = []
await Array.fromAsync([1, 2, 3], async (x) => {
  await sleep(10)
  order.push(x)
  return x
})
// order 一定是 [1, 2, 3]，不会乱序
````

所以：要并发 → `Promise.all`；要顺序、或者源本身是异步迭代器 → `Array.fromAsync`。

## Error.isError()

判断一个值是不是**真的 Error**。

````javascript
Error.isError(new Error())      // true
Error.isError(new TypeError())  // true
Error.isError({})               // false
Error.isError('boom')           // false
````

也不是靠原型查的，伪造的假对象骗不过：

````javascript
Error.isError({ name: 'Error', message: 'x', stack: '' })   // false
Error.isError(Object.create(Error.prototype))               // false
````

它检查的是规范内部的 `[[ErrorData]]` 槽，这才是"真 Error"的标记。

## Iterator.concat()

把多个可迭代对象**惰性**拼成一个。

````javascript
Iterator.concat([1, 2], new Set([3]), 'ab').toArray()
// [1, 2, 3, 'a', 'b']
````

比 `[...a, ...b]` 好在两点：**惰性**（用到才取值，能拼无穷序列）、**不生产中间数组**。

````javascript
// 拿一个无限自然数序列的前 5 个
function* naturals() { let i = 0; while (true) yield i++ }

Iterator.concat(naturals(), [100]).take(5).toArray()
// [0, 1, 2, 3, 4]
````

## Map / WeakMap 的 getOrInsert()

经典的"取不到就设默认值"场景，终于一步搞定。

````javascript
const map = new Map()

// 以前
if (!map.has('key')) map.set('key', [])
map.get('key').push(1)

// 现在
map.getOrInsert('key', []).push(1)
````

还有个"懒创建"版本，只有真需要时才执行工厂函数：

````javascript
map.getOrInsertComputed('key', () => expensiveInit())
````

两者的差别很实际：

| 方法 | 第二个参数 | 什么时候求值 |
|------|-----------|------------|
| `getOrInsert(k, v)` | 直接给值 | **每次都求值**（不管需不需要） |
| `getOrInsertComputed(k, fn)` | 给函数 | 只在 key 不存在时求值 |

所以默认值很贵的时候用 `Computed` 那个。`WeakMap` 也有一模一样的两个方法。

## JSON.parse 能拿到原文

`reviver` 多了第三个参数 `context`，里面有 `source` —— 该值在原始 JSON 文本里的**原样字符**。

````javascript
JSON.parse('{"a": 1e2, "b": "x"}', function (key, value, context) {
  if (key) console.log(key, value, context.source)
  return value
})
// a 100 '1e2'     ← 拿到的是原文 "1e2"，而不是数字 100
// b x   '"x"'
````

这解决了一个老痛点：**大整数精度丢失**。

````javascript
// 以前：18446744073709551616 直接被 Number 吃掉精度
JSON.parse('{"id": 18446744073709551616}').id
// 18446744073709552000

// 现在：拿原文自己转 BigInt
JSON.parse('{"id": 18446744073709551616}', function (k, v, ctx) {
  return k === 'id' ? BigInt(ctx.source) : v
}).id
// 18446744073709551616n
````

配套还有 `JSON.rawJSON()` —— 反向操作，把一段文本原样塞进序列化结果：

````javascript
const raw = JSON.rawJSON('123456789012345678901234567890')
JSON.stringify({ big: raw })
// '{"big":123456789012345678901234567890}'   ← 没丢精度

JSON.isRawJSON(raw)   // true，用来判断某个值是不是 rawJSON 产物
````

> 注意 `JSON.rawJSON()` 只接受**合法的 JSON 文本**，传对象或非法字符串会抛 `SyntaxError`。

## Uint8Array 的 Base64 / Hex 方法

以前浏览器里得靠 `btoa` / `atob`，Node 里靠 `Buffer`。现在标准里自带。

````javascript
const bytes = new Uint8Array([72, 105])

bytes.toBase64()                       // 'SGk='
bytes.toHex()                          // '4869'

Uint8Array.fromBase64('SGk=')          // Uint8Array [72, 105]
Uint8Array.fromHex('4869')             // Uint8Array [72, 105]
````

`toBase64` 支持几个实用选项：

````javascript
new Uint8Array([251, 255]).toBase64({ alphabet: 'base64url' })   // '-_8='
bytes.toBase64({ omitPadding: true })                             // 'SGk'
````

还有"写进已有 buffer"的版本，会返回读了多少、写了多少：

````javascript
const buf = new Uint8Array(4)
buf.setFromBase64('SGk=')
// { read: 4, written: 2 }   buf 前两字节是 [72, 105]
````

对做二进制传输、图片 dataURL 这类活儿，比 `btoa` 那套靠谱多了。

## Math.sumPrecise()

浮点加法会丢有效位，数组累加时这个损失会被放大 —— `reduce` 出来的结果可能错得离谱：

````javascript
[1e100, 1, -1e100].reduce((a, b) => a + b, 0)
// 0    ← 1 被 1e100 直接吞掉，加回来也没了
````

`Math.sumPrecise` 给的是精确和：

````javascript
Math.sumPrecise([1e100, 1, -1e100])
// 1    ← 中间误差被完整保留下来
````

它接受任意可迭代对象：

````javascript
Math.sumPrecise(new Set([1, 2, 3]))   // 6
````

代价是比 `reduce` 慢 —— 它得把中间误差额外记下来、最后再补回去。所以只在精度真的重要时用（统计、金融），普通求和还是 `reduce`。
