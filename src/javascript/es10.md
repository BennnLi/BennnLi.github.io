# ES10（ES2019）

ECMAScript 第 10 版 · 2019 年 6 月发布

## 版本速览
1. `Array.prototype.flat` / `Array.prototype.flatMap`
2. `Object.fromEntries`
3. `String.prototype.trimStart` / `String.prototype.trimEnd`
4. `Symbol.prototype.description`
5. 可选的 catch 绑定：`catch {}` 可省略异常参数
6. `Array.prototype.sort` 优化：排序结果稳定
7. `Function.prototype.toString` 修订：返回精确的源码文本
8. `JSON.stringify` 对孤立代理项输出转义序列
9. JSON 成为 ECMAScript 子集：字符串可直接包含 U+2028 和 U+2029

> ⚠️ **归属更正**：不少清单会把 `String.prototype.matchAll` 列进 ES10，但它实际是
> **ES2020（ES11，ECMA-262 第 11 版）** 引入的特性，因此本文档不含它。
> 它会在 [ES11](/javascript/es11) 中整理。

## Array.prototype.flat / Array.prototype.flatMap
用于展平数组

### Array.prototype.flat

函数签名
````javascript
function flat(depth = 1)
````

默认深度为**1**
````javascript
const array = [[1, 2], 3]
const flatArray = array.flat() // [1, 2, 3]
````

传入 **Infinity** 可展开所有层级
````javascript
const array = [[[1, 2]], 3]
const flatArray1 = array.flat(1) // [[1, 2], 3]
const flatArray2 = array.flat(2) // [1, 2, 3]
const flatArrayInfinity = array.flat(Infinity) // [1, 2, 3]
````

### Array.prototype.flatMap
`array.flatMap(fn)` 等价于先调用一个 `map` 再调用一次 `flat(1)` **，也就是 `array.map(fn).flat(1)`，但比分开两次调用的效率更高
````javascript
const array = [1, 2, [3, 4]]
const flatMapArray = array.flatMap((i) => {
    console.log(i)
    return typeof i === 'number' ? i * 2 : i
})
console.log(flatMapArray)

// 输出结果
// 1
// 2
// [3, 4]
// [2, 4, 3, 4]
````

## Object.fromEntries
`Object.fromEntries` 是 `Object.entries` 的逆向操作，它接收一个键值对数组或可迭代 `Map` 对象，返回一个由这些键值对构成的新对象

````javascript
const obj = { name: 'lee', age: 15 }
const entries = Object.entries(obj) // [['name', 'lee'], ['age', 15]]
const newObj = Object.fromEntries(entries) // { name: 'lee', age: 15 }
console.log(newObj === obj) // false
````

将 `Map` 转换成对象
````javascript
const map = new Map()
map.set('name', 'lee')
const obj = Object.fromEntries(map)
console.log(obj) // { name: 'lee' }
````

## String.prototype.trimStart() 和 trimEnd
`String.prototype.trimStart` 用于删除字符串左边的空格，
````javascript
const str = '    apple '
console.log(str.trimStart()) // 'apple '
````

`String.prototype.trimEnd` 用于删除字符串右边的空格
````javascript
const str = '    apple '
console.log(str.trimEnd()) // '    apple'
````

## Symbol.prototype.description

以前想拿到 Symbol 的描述文字，只能从 `toString()` 的结果里"抠"出来：

````javascript
const sym = Symbol('foo')

// 以前：把 'Symbol(foo)' 截一刀
String(sym).slice(7, -1)   // 'foo'
````

现在有了专门的只读属性：

````javascript
const sym = Symbol('foo')
sym.description           // 'foo'

Symbol().description      // undefined ← 没传描述就是 undefined
Symbol('').description    // ''        ← 传空字符串则是空串
````

几个要点：

- 它是**只读的 getter**，不能赋值
- 没有描述时返回 `undefined`，而 `toString()` 此时返回 `'Symbol()'`
- 它只服务于调试和展示 —— **描述相同的两个 Symbol 依然是不同的值**：

````javascript
Symbol('a') === Symbol('a')   // false
````

## 可选的 catch 绑定

以前即使完全不关心异常对象，也必须写一个参数：

````javascript
// 以前
try {
  return JSON.parse(str)
} catch (e) {          // e 根本没用到，还得占个名字
  return null
}
````

现在可以省略：

````javascript
// 现在
try {
  return JSON.parse(str)
} catch {              // 不需要异常对象时直接省略
  return null
}
````

几个要点：

- 只有在**完全不需要**异常对象时才能省略；省略后作用域里没有这个绑定
- 好处是**表意更明确**："我不关心具体是什么错"
- 常见于"失败就走兜底"的场景：`JSON.parse`、`decodeURIComponent`、`localStorage.getItem` 等

````javascript
// 典型用法：解析失败就用默认值
function safeParse(str, fallback = null) {
  try {
    return JSON.parse(str)
  } catch {
    return fallback
  }
}
````

> 注意：这只是省掉了参数绑定，**并没有**改变错误处理语义 —— 异常依然被捕获，不会再往上抛。

## Array.prototype.sort 稳定性

ES2019 起，规范**要求** `Array.prototype.sort` 是**稳定排序**：比较结果相同的元素，**保持它们原来的相对顺序**。

````javascript
const list = [
  { name: 'A', score: 90 },
  { name: 'B', score: 80 },
  { name: 'C', score: 90 },
  { name: 'D', score: 80 }
]

list.sort((a, b) => a.score - b.score)

// 结果：[B(80), D(80), A(90), C(90)]
// B 仍在 D 之前、A 仍在 C 之前 —— 这就是"稳定"
````

**为什么重要**：稳定排序让"多级排序"变得可行 —— 先按次要字段排，再按主要字段排。

````javascript
const users = [
  { name: '张三', age: 30 },
  { name: '李四', age: 25 },
  { name: '王五', age: 30 }
]

// 第一步：先按姓名排（次要字段）
users.sort((a, b) => a.name.localeCompare(b.name, 'zh'))
// → 李四、王五、张三

// 第二步：再按年龄排（主要字段）
users.sort((a, b) => a.age - b.age)
// → 李四(25)、王五(30)、张三(30)
// 同为 30 岁的王五、张三，保留了第一步按姓名排好的顺序
````

**历史背景**：ES2019 之前规范**不要求**稳定。V8 早期对小数组用插入排序（稳定）、大数组用快速排序（不稳定），于是**同一个数组、不同长度**可能得到不同结果。ES2019 之后，各引擎陆续改用 TimSort 这类稳定算法（V8 从 7.0 / Node 11 起）。

## Function.prototype.toString 修订

ES2019 统一了 `Function.prototype.toString()` 的行为：**返回函数精确的源码文本**，注释和空白都保留。

````javascript
function add(a, b) {
  // 这个注释会被保留
  return a + b
}

add.toString()
// 'function add(a, b) {\n  // 这个注释会被保留\n  return a + b\n}'
````

以前各引擎实现不一：可能去掉注释和多余空白，可能返回被"美化"过的形式。现在规范要求**原样返回源码**。

**对于非源码函数**（宿主提供的内置函数、绑定函数等），返回一个**规范化的占位串**：

````javascript
Math.max.toString()          // 'function max() { [native code] }'
add.bind(null).toString()    // 'function () { [native code] }'
````

几个要点：

- 目的是让**依赖源码字符串的工具**（转译器、压缩器、代码分析、sourcemap）行为可预测
- 返回的是"源码文本"，**绝不能**用作安全判断 —— 函数可以自己改写 `toString` 来伪装：

````javascript
function f() {}
f.toString = () => 'function f() { /* 假的 */ }'
f.toString()   // 完全可控，不能用来做任何安全检查
````

## JSON.stringify 对孤立代理项的处理

先解释概念：JavaScript 字符串是 UTF-16，一个字符可能由**高低两个代理项**（surrogate）组成；如果只出现其中一个（例如手写出来的 `\uD800`），就叫**孤立代理项**（lone surrogate）。

````javascript
'\uD800'              // 孤立的高代理项，本身不是一个完整字符
'\uD83D\uDE00'        // 高低成对 → 一个 emoji 😀
````

**ES2019 之前的问题**：`JSON.stringify` 会把孤立代理项**原样输出**，得到的字符串不是合法的 UTF-16/UTF-8。把它写文件、发网络，或交给 `encodeURIComponent` 时会出问题（抛 `URIError: URI malformed`，或者写入后变成乱码）：

````javascript
JSON.stringify('\uD800')
// ES2019 前：输出里带着"裸"的代理项 —— ill-formed，无法安全编码
````

**ES2019 之后**：改为输出**转义序列**，保证结果是 well-formed 的：

````javascript
JSON.stringify('\uD800')
// 现在：'"\\ud800"'  ← 输出的是反斜杠、u、d、8、0、0 这 6 个字符

JSON.stringify('😀')
// '"😀"'  ← 成对的代理项不受影响，原样输出
````

**关键点：往返依然保持**

````javascript
JSON.parse(JSON.stringify('\uD800')) === '\uD800'   // true
````

变的只是**序列化出来的文本**从"不合法"变成"合法"，解析回来还是同一个值。所以这个修订是"只修不破"的。

## JSON 成为 ECMAScript 的子集

**背景**：JSON 和 JavaScript 的字符串语法本来几乎一致，但有两个字符例外 —— `U+2028`（LINE SEPARATOR）和 `U+2029`（PARAGRAPH SEPARATOR）。

- **JSON** 允许它们出现在字符串**内部**
- **ES2019 之前的 JavaScript** 把它们一律当作**行终止符**，出现在字符串字面量中间会直接**语法错误**

于是出现了一个尴尬局面：一段**合法的 JSON**，原样当 JS 代码写却会报错。

````javascript
// 这是一段合法 JSON（字符串里含 U+2028）
// {"text": "a␨b"}      （␨ 表示 U+2028）

// ES2019 前：把它嵌进 JS 会 SyntaxError
// const data = {"text": "a␨b"}
````

这在**把 JSON 直接嵌进页面**时是真实风险 —— 比如服务端拼接 `var data = {...}` 到 `<script>` 标签里，或者 JSONP。

**ES2019 的修订**：JavaScript 的字符串字面量也允许直接包含 `U+2028` 和 `U+2029`，从此 **JSON 是 ECMAScript 的严格子集**。

````javascript
// ES2019 后：合法
const s1 = 'a\u2028b'   // 单引号字符串
const s2 = "a\u2029b"   // 双引号字符串
const s3 = `a\u2028b`   // 模板字面量
````

> 注意：它们**只在字符串字面量内部**才合法；在字符串外面，`U+2028` / `U+2029` 仍然是行终止符。

## 注意事项

1. `flat()` 默认只展开**一层**，要展平全部层级得传 `Infinity`
2. `flatMap()` 等价于 `map` + `flat(1)`，**只展开一层**，且无法通过参数改变深度
3. `flat()` / `flatMap()` 都会**跳过稀疏数组的空洞**
4. `Object.fromEntries` 是 `Object.entries` 的逆操作；两者串联可以做"对象转换管道"
5. `trimStart` / `trimEnd` 是 `trimLeft` / `trimRight` 的**标准别名**，后者只是兼容性保留
6. 省略 catch 绑定后，作用域里**没有**异常对象；需要错误信息时必须保留参数
7. `sort` 的稳定性是**规范要求**，但只在 ES2019 之后的引擎上成立
8. `Function.prototype.toString()` 的结果**不能用于安全判断**，函数可以自定义它
9. well-formed `JSON.stringify` 只改变**序列化文本**，`JSON.parse` 的往返结果不变
10. 归属别搞混：**`String.prototype.matchAll` 属于 ES2020（ES11）**，不在 ES10
