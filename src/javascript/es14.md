# ES14（ES2023）

ECMAScript 第 14 版 · 2023 年 6 月发布

## 版本速览
1. `findLast()` / `findLastIndex()`
2. 非破坏性数组方法：`toSorted()` / `toReversed()` / `toSpliced()` / `with()`
3. Hashbang 语法写进规范
4. `Symbol` 可以当 `WeakMap` 的键

## findLast() / findLastIndex()

从后往前找，就这点事。

````javascript
const nums = [5, 12, 8, 130, 44]

nums.find(n => n > 10)             // 12   ← 老方法从前往后
nums.findLast(n => n > 10)         // 44   ← 从后往前

nums.findIndex(n => n > 10)        // 1
nums.findLastIndex(n => n > 10)    // 4
````

找不到时的返回值和老方法一致：`undefined` 和 `-1`。

TypedArray 也有这两个。

## 非破坏性数组方法

`sort` / `reverse` / `splice` 都是**就地改**的，这版各配了一个"返回新数组"的版本。

````javascript
const src = [3, 1, 2]

src.toSorted()        // [1, 2, 3]
src.toReversed()      // [2, 1, 3]
src.toSpliced(0, 1)   // [1, 2]
src.with(1, 99)       // [3, 99, 2]

src                   // [3, 1, 2]  ← 从头到尾没动
````

对应关系一目了然：

| 破坏性 | 非破坏性 |
|--------|---------|
| `sort()` | `toSorted()` |
| `reverse()` | `toReversed()` |
| `splice()` | `toSpliced()` |
| `arr[i] = x` | `with(i, x)` |

以前想留原件只能 `[...arr].sort()` 或者先 `slice()` 一份，现在一步到位。写 React / Vue 的状态更新时会舒服很多 —— 不用再担心复制漏了导致原数据被改。

### 几个细节

**`with` 越界会抛错**，不像 `at()` 那样给你 `undefined`：

````javascript
[1, 2, 3].at(99)         // undefined
[1, 2, 3].with(99, 0)    // RangeError: Invalid index : 99
````

负数下标照常能用：`[1, 2, 3].with(-1, 'x')` → `[1, 2, 'x']`。

**`toSorted()` 默认还是按字符串比**，跟 `sort()` 一个老毛病：

````javascript
[10, 9, 100].toSorted()                    // [10, 100, 9]
[10, 9, 100].toSorted((a, b) => a - b)     // [9, 10, 100]
````

**TypedArray 少了 `toSpliced`**：

````javascript
const ta = new Int8Array([3, 1, 2])

typeof ta.toSorted      // 'function'
typeof ta.toReversed    // 'function'
typeof ta.with          // 'function'
typeof ta.toSpliced     // 'undefined'   ← 没有
````

**空位会被填成 `undefined`**。这点和破坏性版本不一样，藏得比较深：

````javascript
Object.keys([1, , 3].toSorted())    // ['0', '1', '2']  空位变成真的 undefined
Object.keys([1, , 3].sort())        // ['0', '1']       空位还是空位
````

平时自己写数组很少造出空位，但接手别人的数据时可能撞上。

## Hashbang 语法

文件第一行的 `#!` 正式写进规范了。以前 Node 自己认得，但严格讲不算合法 JS。

````javascript
#!/usr/bin/env node

console.log('直接执行就行')
````

````bash
chmod +x script.mjs
./script.mjs
````

只有**第一个字符**是 `#` 时才算，别的地方不行。写 CLI 工具时顺手一些，不用再额外配入口脚本。

## Symbol 可以当 WeakMap 的键

以前 `WeakMap` / `WeakSet` 的键必须是对象，现在普通 `Symbol` 也行：

````javascript
const wm = new WeakMap()
const key = Symbol('k')

wm.set(key, 'ok')
wm.get(key)     // 'ok'
````

**但不包括 `Symbol.for()` 注册出来的那种**：

````javascript
wm.set(Symbol.for('reg'), 1)
// TypeError: Invalid value used as weak map key
````

原因也说得通：`Symbol.for` 进的是全局注册表，永远不回收，放进去就失去"弱引用"的意义了。`Symbol()` 造出来的没别的引用就能被回收。

顺便复习一下两者的区别：

````javascript
Symbol('a') === Symbol('a')            // false，每次都是新的
Symbol.for('a') === Symbol.for('a')    // true，全局注册表里同一个
````
