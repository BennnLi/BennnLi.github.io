# ES13（ES2022）

ECMAScript 第 13 版 · 2022 年 6 月发布

## 版本速览
1. 顶层 `await`
2. 类字段：公有实例字段 / 静态字段
3. 私有字段与私有方法 `#name`
4. 静态初始化块 `static { }`
5. 私有成员存在性检查 `#x in obj`
6. `Object.hasOwn()`
7. `Array` / `String` / `TypedArray` 的 `.at()`
8. `Error` 的 `cause` 选项
9. 正则 `d` 标志（匹配索引）
10. 任意模块命名空间名

## 顶层 await

模块顶层就能直接写 `await`，不用再包一层 `async` 函数。

````javascript
// config.mjs
const res = await fetch('/api/config')
export const config = await res.json()
````

**只在 ES Module 里可用**。CommonJS / 普通 script 里是语法错误（实测）：

````text
SyntaxError: await is only valid in async functions and the top level bodies of modules
````

两个典型用途：

````javascript
// 1. 模块初始化前必须先拿到数据（配置、DB 连接、i18n 文案）
export const db = await connectDatabase()

// 2. 动态决定导出什么
export const impl = await (isDev ? import('./mock.js') : import('./real.js'))
````

> 有顶层 `await` 的模块会变成「**异步模块**」—— 静态 `import` 它的模块**会一起等待**。
> 所以别在底层公共模块里滥用，否则整条依赖链都会被拖慢。
> 动态 `import()` 不受这个约束，不会阻塞调用方。

## 类的新能力

### 1. 公有字段与静态字段

````javascript
class Pub {
  instance = 1        // 公有实例字段
  static stat = 2     // 公有静态字段
  declared            // 只声明不赋值 → undefined
}

new Pub().instance    // 1
Pub.stat              // 2
new Pub().declared    // undefined
'instance' in new Pub()   // true
````

以前只能在构造函数里 `this.instance = 1`，现在可以在类体里直接声明。字段是**实例自有属性**，不在原型上。

### 2. 私有字段与私有方法

````javascript
class Counter {
  #count = 0                        // 私有字段
  static #total = 100               // 静态私有字段
  #inc() { this.#count++ }          // 私有方法
  static #getTotal() { return Counter.#total }
  static { Counter.#total += 1 }    // 静态块里也能访问私有成员

  bump() { this.#inc(); return this.#count }
  static total() { return Counter.#getTotal() }
}
````

`#` 前缀是**真正的私有**（不同于 `_name` 这种约定）：

| 性质 | 表现 |
|------|------|
| 外部访问 | **语法上就写不出来**，`p.#count` 直接 SyntaxError |
| 出现在 `Object.keys` 吗 | ❌ 不出现 |
| 出现在 `Reflect.ownKeys` 吗 | ❌ 不出现（实测只有公有字段） |
| 未声明就使用 | **解析阶段**报错，不是运行时报错 |
| 子类声明同名 `#x` | 与父类的**互不影响**（各自独立） |
| `delete p.#x` | ❌ 不允许 |

### 3. 静态初始化块 `static { }`

````javascript
class Config {
  static values = []

  static {
    // 可以有语句、try/catch，也能访问私有成员
    try {
      Config.values = JSON.parse(readFileSync('./config.json', 'utf8'))
    } catch {
      Config.values = []
    }
  }
}
````

相当于"类的初始化代码块"，**在类定义时执行一次**。比 `static x = (() => { ... })()` 这种 IIFE 写法清晰得多。

### 4. 私有成员存在性检查 `#x in obj`

````javascript
class Priv {
  #count = 0
  static isPriv(o) { return #count in o }
}

Priv.isPriv(new Priv())    // true
Priv.isPriv({})            // false
Priv.isPriv(new Other())   // false —— 不同类的 #count 互不相通
````

这是**「品牌检查」（brand check）**的标准做法：判断对象是不是本类实例，而且**无法通过伪造原型链绕过**。

> 实测：右侧必须是**对象**，`#count in 1` 会抛
> `TypeError: Cannot use 'in' operator to search for '#count' in 1`

### 附：字段初始化顺序（实测）

````text
基类字段 → 基类构造函数体 → 子类字段 → 子类构造函数体
````

实测 `new Child()` 里各步骤的输出顺序为 `base 字段, base 构造, child 字段, child 构造` ——
即**子类字段在 `super()` 返回之后、子类构造函数体之前**初始化。

## Object.hasOwn()

````javascript
Object.hasOwn({ a: 1 }, 'a')          // true
Object.hasOwn({}, 'toString')         // false —— 只看自有属性
Object.hasOwn({}, 'hasOwnProperty')   // false
````

它替代 `obj.hasOwnProperty(k)`，解决后者的两个坑：

**坑一：`Object.create(null)` 的对象没有 `hasOwnProperty` 方法**（实测 `typeof nullProto.hasOwnProperty` 是 `undefined`），直接调用会抛错：

````javascript
const nullProto = Object.create(null) //
nullProto.x = 1

nullProto.hasOwnProperty('x')   // ❌ TypeError
Object.hasOwn(nullProto, 'x')  // ✅ true
````

**坑二：属性名撞车** —— 对象自己有个 `hasOwnProperty` 字段就会遮蔽原型方法。

## .at()

让"倒数第几个"有了统一的写法：

````javascript
const arr = ['a', 'b', 'c']

arr.at(0)      // 'a'
arr.at(-1)     // 'c'   ← 负数从末尾数
arr.at(-3)     // 'a'
arr.at(-4)     // undefined（越界不报错）
arr.at(99)     // undefined

arr[-1]        // undefined ← 对比：这不是"倒数第一个"
arr[arr.length - 1]   // 'c'  ← 以前的写法
````

`String` 和 `TypedArray` 也有：

````javascript
'abc'.at(-1)                     // 'c'
new Int8Array([1, 2, 3]).at(-1)  // 3
````

## Error 的 cause 选项

包装底层错误时，把原始错误挂到 `cause` 上：

````javascript
try {
  await connect()
} catch (err) {
  throw new Error('请求失败', { cause: err })   // 保留根因
}
````

````javascript
const root = new Error('根因：连接超时')
const wrapped = new Error('请求失败', { cause: root })

wrapped.message            // '请求失败'
wrapped.cause === root     // true
wrapped.cause.message      // '根因：连接超时'
````

三个注意点（实测）：

1. **不传 `cause` 选项时该属性不会被创建**：`'cause' in new Error('x')` 为 `false`
2. `cause` **不可枚举**，所以 `JSON.stringify(err)` 得到 `{}`，序列化时要手动取
3. `cause` 也**不出现在 `stack` 里**，只看日志很容易漏掉根因

## 正则 d 标志（匹配索引）

普通的 `exec` 结果只知道"匹配了什么"，`d` 标志让你同时知道"在哪儿"：

````javascript
const m = /(\d)(\d)/d.exec('12')

m[0]          // '12'
m.indices     // [[0, 2], [0, 1], [1, 2]]
//               ↑整体     ↑第1组  ↑第2组
````

每个元素是 `[start, end]`（**左闭右开**），可以直接切片还原：

````javascript
'12'.slice(...m.indices[0])   // '12'
````

命名组的索引在 `indices.groups` 下（实测）：

````javascript
const n = /(?<y>\d{4})-(?<m>\d{2})/d.exec('2022-06')

n.indices.groups              // { y: [0, 4], m: [5, 7] }
'2022-06'.slice(...n.indices.groups.y)   // '2022'
````

不带 `d` 时 `m.indices` 是 `undefined`。

**用途**：语法高亮、搜索命中高亮、需要精确知道匹配位置的文本处理。

## 任意模块命名空间名

ES2022 允许用**字符串**做导出/导入名（以前必须是合法标识符）：

````javascript
// names.mjs
const internal = { a: 1, b: 2 }
export { internal as 'my-namespace' }
export { internal as '带空格 的名字' }
export const normal = 'normal'
````

三种使用方式：

````javascript
// 1. 字符串形式的具名导入
import { 'my-namespace' as a } from './names.mjs'

// 2. 命名空间 + 方括号取值
import * as ns from './names.mjs'
ns['my-namespace']      // { a: 1, b: 2 }

// 3. 动态导入同理
const m = await import('./names.mjs')
m['带空格 的名字']       // 连带空格的名字都合法
````

**用途**：主要给**非 JS 工具链**做桥接 —— 比如 WASM 或其他语言编译产物的导出名常常不是合法 JS 标识符，以前只能手动映射成一个中间对象，现在可以原样透出。

## 注意事项

1. 顶层 `await` 只在 ES Module 可用；它会**阻塞静态导入它的模块**
2. 类字段是**实例自有属性**；只声明不赋值时值为 `undefined`（不是"不创建"）
3. 私有成员用 `#`，是**真正私有**（语法层面不可访问）；`_name` 只是团队约定
4. 类内使用未声明的 `#x` 是**解析期错误**，不是运行期错误
5. `#x in obj` 的右侧必须是对象，否则抛 `TypeError`
6. `Object.hasOwn` 只查**自有**属性，原型链上的返回 `false`
7. `String.prototype.at()` 按**码元**索引，取 emoji 要先 `[...str]`
8. `Error` 的 `cause` **不可枚举**、不在 `stack` 里，也不传时根本不创建
9. 正则 `d` 标志的 `indices` 是 `[start, end]` **左闭右开**区间
10. 字符串形式的模块名主要用于与非 JS 工具链对接，日常业务代码很少需要
