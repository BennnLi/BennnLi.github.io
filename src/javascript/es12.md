# ES12（ES2021）

ECMAScript 第 12 版 · 2021 年 6 月发布

## 版本速览
1. `String.prototype.replaceAll()`
2. `Promise.any()`（配合 `AggregateError`）
3. 逻辑赋值运算符 `&&=` / `||=` / `??=`
4. 数字分隔符 `1_000_000`
5. `WeakRef` / `FinalizationRegistry`
6. `Array.prototype.sort` 精度改进

## String.prototype.replaceAll()

一次性替换**所有**匹配，不用再写正则或 `split` + `join`。

````javascript
'a-b-c'.replaceAll('-', '+')   // 'a+b+c'
'a-b-c'.replace('-', '+')      // 'a+b-c'  ← 只换第一个

'a.b'.replaceAll('.', '-')     // 'a-b'    ← 字符串参数按字面量处理，不用转义
'a1b2'.replaceAll(/\d/g, '#')  // 'a#b#'
````

> 传正则时**必须带 `g` 标志**，否则直接抛错：
> `TypeError: String.prototype.replaceAll called with a non-global RegExp argument`

## Promise.any()

只要**有一个成功**就 resolve（取最先成功的那个）；**全部失败**才 reject，抛 `AggregateError`。

````javascript
await Promise.any([Promise.reject('x'), Promise.resolve('ok')])   // 'ok'

try {
  await Promise.any([Promise.reject('x'), Promise.reject('y')])
} catch (e) {
  e.name     // 'AggregateError'
  e.errors   // ['x', 'y']
}
````

四个 Promise 组合方法的分工：

| 方法 | 成功条件 | 失败条件 |
|------|---------|---------|
| `all` | 全部成功 | 任一失败（短路） |
| `allSettled` | 全部结束 | 几乎不会 |
| `any` | **任一成功** | 全部失败 |
| `race` | 第一个结束 | 第一个结束是失败 |

## 逻辑赋值运算符

`&&=` / `||=` / `??=` 是"逻辑运算 + 赋值"的简写，**且带短路**。

- `a &&= b` 等价于 `a && (a = b)` —— `a` 为真值时赋值
- `a ||= b` 等价于 `a || (a = b)` —— `a` 为假值时赋值
- `a ??= b` 等价于 `a ?? (a = b)` —— `a` 为 `null` / `undefined` 时赋值

````javascript
let a = 0
a ||= 'fallback'    // 'fallback'  （0 是假值 → 赋值）

let b = 0
b ??= 'fallback'    // 0           （?? 只认 null/undefined → 不赋值）

let c = null
c &&= 'fallback'    // null        （c 是假值 → 不赋值）

obj.a.b ??= 'x'     // 属性不存在时创建并赋值，比一堆 if 判断简洁
````

> 注意**短路**：条件不满足时，右侧表达式根本不会求值。

## 数字分隔符

用 `_` 给数字加可读性分隔，**不影响值**。

````javascript
1_000_000        // 1000000
1_000.123_456    // 1000.123456
0xFF_FF          // 65535
1_0n             // 10n，BigInt 同样支持
````

规则：只能放在**数字之间** —— 不能开头、结尾、连续，也不能紧贴小数点。

````javascript
1__0    // ❌ SyntaxError
10_     // ❌ SyntaxError
1_.0    // ❌ SyntaxError
1._0    // ❌ SyntaxError
````

## WeakRef / FinalizationRegistry

`WeakRef` 持有对象的**弱引用**（不阻止 GC 回收）；`FinalizationRegistry` 在对象被回收后收到通知。

````javascript
const target = { name: 'obj' }
const ref = new WeakRef(target)

ref.deref()      // 对象还在 → 返回它；已被回收 → 返回 undefined

const registry = new FinalizationRegistry((held) => {
  console.log('被回收了', held)
})
registry.register(target, 'held-value')   // 第二个参数是"附带值"
````

> 两者都**不适合承载业务逻辑**：GC 时机不确定，回调可能永远不触发，也可能等到页面关闭才触发。
> 只适合缓存、调试、诊断这类"尽力而为"的场景。

## Array.prototype.sort 精度改进

`sort()` 有些边角场景允许实现自己决定顺序（比较函数不满足全序、遇到 `NaN`、稀疏数组的空位等），不同引擎可能给出不同结果。这版把这类"实现自由"的场景**减少**了。

正常排序感受不到变化。别和 ES2019 那次搞混 —— **ES2019 要求 sort 必须稳定，ES2021 这次是减少"实现可自由决定"的剩余场景**，两次不同的修正。

## 注意事项

1. `replaceAll` 传正则时**必须带 `g`**；传字符串则按字面量处理，不需要转义
2. `??=` 只对 `null` / `undefined` 赋值；`||=` 对所有假值（`0` / `''` / `false` / `NaN`）都赋值
3. 逻辑赋值运算符**带短路**：条件不满足时右侧表达式不会被求值
4. 数字分隔符只是语法糖，`1_000 === 1000`
5. `WeakRef.deref()` 随时可能返回 `undefined`，用前必须判空
6. `FinalizationRegistry` 的回调**不保证执行时机**，不要依赖它做资源清理
7. `Promise.any` 全失败时抛的是 `AggregateError`，各失败原因在 `.errors` 里
