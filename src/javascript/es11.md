# ES11（ES2020）

ECMAScript 第 11 版 · 2020 年 6 月发布

## 版本速览
1. 可选链?.
2. 空值合并操作符??
3. 字符串 / 正则匹配增强 String.prototype.matchAll()
4. BigInt 类型

## 可选链?.
引入了可选链操作符 ?.，用于安全地访问嵌套属性。

````javascript
const user = {};
console.log(user?.profile?.name); // undefined
````

优化多层取值的判断逻辑
````javascript
// 以前
if (user && user.profile && user.profile.address) {
    // TODO
}

// 现在
if (user?.profile?.address) {
    // TODO
}
````

## 空值合并??
用于在左侧值为 null 或 undefined 时返回右侧值
````javascript
const num = null ?? 1
````

只对 null 和 undefined 生效，其它假值一律视为有效值，避免因 `0`, `''` 等可转换成 `false` 的值导致的取值错误问题
````javascript
const num1 = 0 || 10 // 10
const num2 = 0 ?? 10 // 0
````

## String.prototype.matchAll()
`matchAll` 用一个字符串和一个正则表达式做匹配，返回**所有匹配结果的迭代器**（不是数组，所以要用 `[...]` 或 `for...of` 展开）。

> ⚠️ 正则**必须带 `g` 标志**，否则直接抛错：
> `TypeError: String.prototype.matchAll called with a non-global RegExp argument`
>
> 与 `str.match(/.../g)` 的区别：后者只返回整体匹配的字符串数组，**没有捕获组、没有 index**；
> `matchAll` 的每条结果都带捕获组和 `index`。

````javascript
const str = `
    <html>
        <body>
            <div>第一个div</div>
            <p>这是个p</p>
            <div>第二个div</div>
            <span>这是个span</span>
        </body>
    </html>
    `

const matched = [...str.matchAll(/<div>(.*)<\/div>/g)];
console.log(matched)

/**
 * 输出（其中 input 为 str 字符串）
 * [
 *  ['<div>第一个div</div>', '第一个div', index: 39, input: 'xx', groups: undefined],
 *  ['<div>第二个div</div>', '第二个div', index: 93, input: 'xx', groups: undefined]
 * ]
 */
````

## BigInt 类型
javascript 中所能表示的数字的最大范围可以用 `Number.MAX_SAFE_INTEGER` 表示
````javascript
console.log(Number.MAX_SAFE_INTEGER) // 9007199254740991, 及 2 ** 53 -1
console.log(2 ** 53 - 1 === Number.MAX_SAFE_INTEGER) // true
````

超过这个范围的数值会出现精度丢失的问题
````javascript
const num1 = Number.MAX_SAFE_INTEGER + 1 // ✅ 9007199254740992
const num2 = num1 + 1 // ❌ 9007199254740992
````

BigInt 是 ES11 新引入的一种数据类型，专门用于处理超过 `Number.MAX_SAFE_INTEGER` 的数字

如何定义一个 BigInt
1. 数值 + n 的形式
````javascript
const num1 = 100n
console.log(num1, typeof num1) // 100n 'bigint'
````

2. BigInt 函数
````javascript
// BigInt 函数，注意传递给函数参数可以是  bigint | boolean | number | string。如果是 string 的话必须确保 string 能被转成 number，如 '1' -> 1，'1n' 无法转换成 number，所以传 '1n' 将会报错
const num2 = BigInt(1) // ✅ 1n
const num3 = BigInt('1') // ✅ 1n
const num4 = BigInt(true) // ✅ 1n
const num5 = BigInt(1n) // ✅ 1n
const num6 = BigInt('1n') // ❌ SyntaxError: Cannot convert 1n to a BigInt
````

BigInt 类型支持几乎所有的运算符
````javascript
let num1 = 1n
let num2 = 2n
console.log(
    num1 + num2,
    num1 - num2,
    num1 * num2,
    num1 / num2,
    num1 % num2,
    num1 ** num2,
    typeof num1,
    ++num1,
    --num1,
) // 3n -1n 2n 0n 1n 1n 'bigint' 2n 1n
````

但除了一元加号运算符 +
````javascript
let num1 = 1n
console.log(-num1) // ✅ -1n
console.log(+num1) // ❌ Uncaught TypeError: Cannot convert a BigInt value to a number
````

### 为什么 `+num1` 会报错，而 `-num1` 不会

关键在于：**一元 `+` 不是"取正号"，而是"强制转换成 Number"的运算符** —— 它和 `Number(x)` 是同一个意思。

而 `-` / `~` / `!` 在规范里属于**数值运算 / 布尔转换**，各自都有 BigInt 分支：

| 表达式 | 规范里执行的抽象操作 | 对 BigInt |
|--------|---------------------|-----------|
| `+x` | `ToNumber(x)` | ❌ 抛 TypeError |
| `-x` | `ToNumeric(x)` 后按类型分支 | ✅ 走 `BigInt::unaryMinus` |
| `~x` | `ToNumeric(x)` 后按类型分支 | ✅ 走 `BigInt::bitwiseNOT` |
| `!x` | `ToBoolean(x)` | ✅ 布尔转换不丢精度 |

- **`ToNumeric`** 保留数值类型：Number 还是 Number，BigInt 还是 BigInt
- **`ToNumber`** 强制转成 Number，而规范明确规定：**对 BigInt 必须抛 TypeError**

**为什么 `ToNumber(BigInt)` 要抛错？** 因为转换可能丢精度：

````javascript
Number(2n ** 53n)         // 9007199254740992
Number(2n ** 53n + 1n)    // 9007199254740992   ← 两个不同的 BigInt 变成了同一个 Number
````

设计原则是：**BigInt 与 Number 是两个平行的数值域，不允许隐式互转**。凡是可能丢精度的转换，都必须由你显式写出来（`Number(x)`），自己承担后果。

````javascript
let num1 = 1n

-num1          // -1n    ✅ 精确，原生支持
~num1          // -2n    ✅ 原生支持
!num1          // false  ✅ 布尔转换
+num1          // ❌ TypeError: Cannot convert a BigInt value to a number
+0n            // ❌ 连 0n 也不行

Number(num1)   // 1      ✅ 显式转换允许（可能丢精度）
num1 * 1n      // 1n     ✅ 留在 BigInt 域
`${num1}`      // '1'    ✅ 字符串化
num1 + ''      // '1'    ✅ 走字符串拼接，不经过 ToNumber
````

### 不能与 Number 混合运算

````javascript
1n + 1    // ❌ TypeError: Cannot mix BigInt and other types, use explicit conversions
1n - 1    // ❌ 同上
1n * 2    // ❌ 同上
1n / 2    // ❌ 同上
1n ** 2   // ❌ 同上
1n & 1    // ❌ 同上
````

只要有一个操作数不是 BigInt 就报错 —— 必须先显式转换，或者让两边都带 `n`。

### 但「比较」是特例，允许混合

规范单独为 BigInt / Number 的比较留了口子（按数学值比较，不做类型转换）：

````javascript
1n == 1      // true    ← 宽松相等允许
1n === 1     // false   ← 严格相等不转换，类型不同
1n < 2       // true    ← 关系比较允许
1n > 0       // true
````

⚠️ 但 `includes` / `Set` / `Map` 用的是 **SameValueZero**，不做混合比较：

````javascript
[1n, 2n].includes(1)      // false   ← 1n 与 1 被视为不同值
new Set([1n, 1]).size     // 2       ← 同上
````

### 数值语义上的四个差异

**① 除法是整数除法（向零截断）**

````javascript
7n / 2n      // 3n     （而 7 / 2 = 3.5）
-7n / 2n     // -3n    （向零截断，不是 -4n）
7n % 3n      // 1n
-7n % 3n     // -1n    （余数符号跟被除数）
````

**② 没有 `-0`、`NaN`、`Infinity`**

````javascript
0n === -0n        // true，且 -0n 就是 0n
BigInt(Infinity)  // ❌ RangeError: ... because it is not an integer
BigInt(NaN)       // ❌ RangeError: ... because it is not an integer
````

**③ 除以 0 直接抛错**（而不是像 Number 那样得到 `Infinity`）

````javascript
1 / 0      // Infinity
1n / 0n    // ❌ RangeError: Division by zero
````

**④ 没有无符号右移 `>>>`**

BigInt 没有固定位宽，`>>>` 在语义上无法定义：

````javascript
8n >> 1n     // 4n
1n << 3n     // 8n
1n >>> 1n    // ❌ TypeError: BigInts have no unsigned right shift, use >> instead
````

### `Math` 全部不可用

````javascript
Math.max(1n, 2n)   // ❌ TypeError: Cannot convert a BigInt value to a number
Math.sqrt(4n)      // ❌ 同上
Math.round(1n)     // ❌ 同上
````

需要自己实现，或先 `Number(x)` 转换（注意精度）。

### JSON 序列化会报错

````javascript
JSON.stringify({ id: 1n })
// ❌ TypeError: Do not know how to serialize a BigInt

JSON.stringify([1n])
// ❌ 同上
````

因为 JSON 规范里根本没有 BigInt 类型。三种解法：

````javascript
// 1. 自定义 replacer，序列化成字符串
JSON.stringify({ id: 1n }, (k, v) => typeof v === 'bigint' ? v.toString() : v)
// '{"id":"1"}'

// 2. 先手动转字符串
JSON.stringify({ id: 1n.toString() })

// 3. 从一开始就用字符串存大整数（最省事，也最推荐）
````

> 反向也有坑：`JSON.parse` 会把大整数解析成 **Number**，照样丢精度：
> ````javascript
> JSON.parse('{"id":18446744073709551616}').id   // 18446744073709552000  ← 已经丢了
> ````
> 所以大整数在 JSON 里应当用**字符串**传输，需要时再 `BigInt(str)` 还原。

### 输出与进制转换

````javascript
const big = 2n ** 64n

big.toString()               // '18446744073709551616'
big.toString(16)             // '10000000000000000'
big.toString(2)              // 65 位二进制，不丢精度
big.toLocaleString('en-US')  // '18,446,744,073,709,551,616'   ← 带千分位
String(big)                  // '18446744073709551616'
````

`toString(radix)` 支持任意进制且**大数也不丢精度** —— 这是 Number 做不到的。

### 转换边界与两个坑

````javascript
BigInt(1)          // 1n
BigInt(1n)         // 1n
BigInt(true)       // 1n
BigInt('1')        // 1n
BigInt('0x1f')     // 31n   ← 支持十六进制字符串
BigInt('0b101')    // 5n    ← 支持二进制字符串
BigInt(' 12 ')     // 12n   ← 会去掉首尾空白

BigInt('')         // 0n    ⚠️ 空字符串会变成 0，而不是报错！
BigInt('1.5')      // ❌ SyntaxError: Cannot convert 1.5 to a BigInt
BigInt(1.5)        // ❌ RangeError: ... because it is not an integer
BigInt('abc')      // ❌ SyntaxError
BigInt()           // ❌ TypeError: Cannot convert undefined to a BigInt
````

**坑一：`BigInt` 不是构造函数**

它是个**普通函数**，只能用 `BigInt(x)` 调用，不能 `new`：

````javascript
new BigInt(1)   // ❌ TypeError: BigInt is not a constructor
````

**坑二：别用 Number 字面量去构造 BigInt**

这是最隐蔽的一个 —— **字面量在解析阶段就已经丢精度了**：

````javascript
9007199254740993          // 9007199254740992        ← 字面量本身就已经错了！
9007199254740993n         // 9007199254740993n       ✅

BigInt(9007199254740993)  // 9007199254740992n       ❌ 传进去的已经是错的值
````

**所以大整数一定要写成 `123n` 字面量，或者用字符串 `BigInt('123')`。**

### 定宽截断：`BigInt.asIntN` / `BigInt.asUintN`

需要模拟"固定位宽整数"（如 64 位、32 位运算）时用：

````javascript
BigInt.asUintN(8, 257n)     // 1n                        ← 取低 8 位（257 = 0b100000001）
BigInt.asIntN(8, 255n)      // -1n                       ← 按有符号解释
BigInt.asUintN(64, -1n)     // 18446744073709551615n     ← 64 位全 1
````

**注意事项汇总**

1. `typeof 1n` 是 `'bigint'`，`Object.prototype.toString.call(1n)` 是 `'[object BigInt]'`
2. `1n === 1` 为 `false`；跨类型比较要用 `==` 或先显式转换
3. 与 Number 混合运算一律报错，必须显式转换
4. `Math` 不可用，`>>>` 不支持
5. 除法是整数除法；除以 0 会抛 `RangeError`
6. `JSON.stringify` 会报错，大整数建议用**字符串**在 JSON 里传输
7. 优先用 `123n` 字面量，避免 `BigInt(numberLiteral)` 造成二次精度损失
8. 网络 / 存储层（JSON、数据库驱动）通常不认 BigInt，边界处要记得转字符串



## Promise.allSettled()
`Promise.allSettled` 接收一个可迭代的对象并返回一个 `Promise`, 这个 `Promise` 会等到所有的 `Promise` 都**敲定
(fulfilled/rejected)**后 `fulfilled`.

> `Promise.allSettled` 返回的 `Promise` 只会 `fulfilled`, 用不 `rejected`

该 `Promise` 的兑现值为数组, 数组中每项代表可迭代对象中 `Promise` 的兑现结果:
1. status: 为 `fulfilled` 或 `rejected`, 代表 promise 的状态
2. value: status = fulfilled 时存在, 代表 promise fulfilled 的结果
3. reason: status = rejected 时存在, 代表 promise rejected 的原因
````typescript
Array<{
    status: 'fulfilled'
    value: any,
} | {
    status: 'rejected',
    reason: any
}>
````

当多个任务没有关联时可以并发执行
````javascript
const sleep = (ms) => new Promise(resolve => setTimeout(resolve, ms))
const task1 = async () => {
    await sleep(1000)
    return true
}
const task2 = async () => {
    await sleep(2000)
    throw new Error('task2 error')
}
Promise.allSettled([task1(), task2()]).then(resList => { console.log(resList) })

// 输出结果
// [
//   { status: 'fulfilled', value: true },
//   {
//     status: 'rejected',
//     reason: Error: task2 error
//         at task2 (d:\develop\css\test.js:49:11)
//         at async Promise.allSettled (index 1)
//   }
// ]
````

前面提到 `Promise.allSettled` 的入参是一个可迭代对象, 所以上面的例子中除了将 `task1()` 和 `task2()` 放在数组中, 也可以放在其他的可迭代对象中, 如 `Set`
````javascript
Promise.allSettled(new Set([task1(), task2()])).then(resList => { console.log(resList) })
````

入参中的每项可以是任意非 promise 的值, 会隐式的包装成 fulfilled 的 promise
````javascript
Promise.allSettled([1, true]).then(result => { console.log(result) })
// 等同于
Promise.allSettled([Promise.resolve(1), Promise.resolve(true)]).then(result => { console.log(result) })
````

### Promise 函数对比

| 方法 | 何时 resolve | 何时 reject	适合场景 |
|-|-|-|
| Promise.all | 全部成功 | 第一个失败（短路） | 后续步骤强依赖全部成功 |
| Promise.allSettled | 全部 settled	几乎不会（仅迭代出错） | 需要逐项报告结果 |
| Promise.race | 第一个 settled	| 第一个 settled 是失败 | 超时控制 |
| Promise.any | 第一个成功 | 全部失败（AggregateError） | 多源取最快可用 |


## globalThis
全局对象的"通用名字"

### 不同环境下的全局对象

| 环境 | 全局对象名 |
|-|-|
| 浏览器主线程 | window |
| Web / Service Worker | self |
| Node.js | global |

以前想要拿到全局对象, 必须逐个判断
````javascript
let g
if (typeof window !== 'undefined') g = window
else if (typeof global !== 'undefined') g = global
else if (typeof self !== 'undefined') g = self
````

现在可以直接使用 `globalThis`

### 常见用途
1. 运行环境判断
````javascript
const isBrowser = typeof globalThis.window !== 'undefined'
const isNode = typeof globalThis.process?.versions?.node !== 'undefined'
````

2. 挂载全局属性
````javascript
globalThis.myVar = { version: '1.0.0' }
````


## 模块化增强

ES2020 在模块系统上补了三块：运行时导入、模块自身的元信息、命名空间再导出。

### 动态 import()

静态 `import` 有三个限制：只能在模块顶层、路径必须是字面量、加载时机在解析阶段就定死了。动态 `import()` 把这三条都打破了。

````javascript
// 返回 Promise，解析为「模块命名空间对象」
const mod = await import('./heavy.js')
console.log(mod.default, mod.named)
````

**它拿到的东西和静态 import 完全一样**（实测同一个对象）：

````javascript
import * as staticNs from './a.mjs'

const dyn = await import('./a.mjs')
dyn === staticNs      // true —— 同一个模块命名空间对象
Object.keys(dyn)      // ['default', 'meta', 'x', 'y']
````

常见用途
````javascript
// 1. 条件导入
if (needChart) {
  const { Chart } = await import('./chart.js')
}

// 2. 按需加载（这一句就是打包器的「代码分割点」）
button.onclick = async () => {
  const { exportPdf } = await import('./export-pdf.js')
  exportPdf()
}

// 3. 运行时拼路径
const page = await import(`./pages/${name}.js`)
````

### import.meta

模块自身的元信息对象，最常用的是 `import.meta.url`：

````javascript
console.log(import.meta.url)
// Node:   file:///D:/project/src/main.mjs
// 浏览器:  https://example.com/assets/main.js
````

**最常见的用途：定位与当前模块同目录的资源**

````javascript
// 拼出同目录文件的绝对 URL
const assetUrl = new URL('./logo.png', import.meta.url)
// file:///D:/project/src/logo.png
````

**在 ESM 里替代 CJS 的 `__dirname` / `__filename`**

````javascript
import { fileURLToPath } from 'node:url'
import path from 'node:path'

const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)
````

**三个注意点**

1. **只在 ES Module 里可用** —— 在 CJS 文件里写会直接报语法错误（实测）：
   `SyntaxError: Cannot use 'import.meta' outside a module`
2. 它的字段**由宿主环境扩展**，不是规范统一定死的，用之前最好判断：
   - Node：`import.meta.url`、`import.meta.resolve()`（实测可用，返回绝对 file URL）
   - Vite：注入 `import.meta.env`、`import.meta.hot`
3. `import.meta` 是**每个模块各自独立**的 —— 不同模块里 `url` 不同

### export * as ns from

把另一个模块的命名空间**整体再导出**，一步完成：

````javascript
// 以前：必须两步
import * as ns from './a.mjs'
export { ns }

// ES2020：一步
export * as ns from './a.mjs'
````

## 属性枚举顺序（规范明确化）

ES2020 把属性的枚举顺序**写进了规范**，不再是"各引擎约定俗成"。

规则（针对自有属性）：

1. **整数索引键**：按**数值升序**排在最前面
2. **字符串键**：按**插入顺序**
3. **Symbol 键**：按插入顺序，且**不参与** `for-in` / `Object.keys`

````javascript
const o = { b: 1, 2: 2, a: 3, 1: 4 }

Object.keys(o)        // ['1', '2', 'b', 'a']
// for-in 的顺序与它完全一致
````

注意 `'1'` 和 `'2'` 虽然写在源码后面，但因为属于**整数索引**，被提到了最前面。

**`for-in` 与 `Object.keys` 的差异**

两者的**顺序规则一致**，但**集合范围不同**：

| | 范围 |
|---|------|
| `Object.keys` | 只含**自有可枚举**属性 |
| `for-in` | 会**沿原型链**收集可枚举属性 |

**这一项严格说不是"新语法"**，而是把原本不确定的行为变成了**保证**。日常代码不需要刻意处理，但知道有保证之后，就可以放心依赖它（比如依赖"整数键升序"来实现有序对象）。

## 注意事项

1. `?.` 只保护**它左边那一层**：`obj?.x.y` 在 `x` 为 `undefined` 时仍然会抛错
2. `?.` 和 `??` **不能与 `||` / `&&` 无括号混用**，否则是 `SyntaxError`
3. `??` 只对 `null` / `undefined` 生效；`0`、`''`、`false`、`NaN` 都算有效值
4. `matchAll` 的正则**必须带 `g` 标志**，且返回的是**迭代器**（要 `[...]` 或 `for...of`）
5. `BigInt` 不能与 Number 混合运算、不能用 `Math`、不能直接 `JSON.stringify`
6. `Promise.allSettled()` **永不 reject**，但失败信息都躺在 `reason` 里 —— 不检查就会静默通过
7. `globalThis` 是为数不多在 ESM / 严格模式下都可靠的全局引用（那里 `this` 是 `undefined`）
8. 动态 `import()` 的路径要保留**可静态分析的前缀**，否则打包器无法处理
9. `import.meta` **只在 ES Module 中可用**；其字段由宿主环境扩展，别假设都存在
10. `for-in` 的顺序有规范保证，但它的**集合范围包含原型链**，与 `Object.keys` 不同
